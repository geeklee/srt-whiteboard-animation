本仓库线稿生成阶段的**默认视觉语言**是小黑 IP，来自
[ian-xiaohei-illustrations](https://github.com/helloianneo/ian-xiaohei-illustrations)（作者 Ian，MIT）。
署名与 vendoring 范围见 [NOTICE.md](NOTICE.md)，许可见 [LICENSE](LICENSE)。

一句话：**画面语言用小黑，编排与渲染仍用本仓库的 SRT 白板管线。**

## 覆盖规则

上游是为「文章正文配图」设计的，本仓库要把图变成**逐区域绘制的白板动画**。
下面五条以本仓库为准，与上游原文冲突时**覆盖原文**：

| # | 上游原文 | 本仓库要求 | 为什么 |
|---|---|---|---|
| 1 | 纯白背景，明确禁止米色/纸感 | **暖米黄纸底 `#F5EBD7`，禁止纯白** | 渲染器采样原图四角识别背景并统一涂成画布底色 `#F6F1E3`；纯白底会让"纸张感"消失，且与本仓库既有视觉规范冲突 |
| 2 | 必须有 5-8 处红橙蓝中文手写批注 | **画面内不得出现任何文字**（词、字母、数字、标签、标题都不行） | 字幕已经承担全部解释职责；图内文字会与字幕重复，且笔迹渲染出的手写字容易糊 |
| 3 | 红/橙/蓝用于批注文字 | 红/橙/蓝**只作非文字的少量点缀**（箭头、路径、强调块、状态色） | 保留上游的颜色语义，但载体从文字换成图形 |
| 4 | "如果用户要求生成就不要停下来等确认" | **必须遵守本仓库的确认关卡**，每步停下等确认 | 渲染成本高，改图代价大；确认关卡是本仓库工作流的核心 |
| 5 | 按文章段落配 4-8 张 | **张数 = SRT 分幕数**（`parse_srt.py` 按 25–35 秒/幕给出建议） | 分幕依据是字幕时间轴，不是段落 |

上游其余内容全部适用，尤其是这些**不要放松**的部分：小黑必须承担核心动作（去掉小黑后隐喻还成立
就说明小黑是装饰）、一张图只讲一个核心结构、原创隐喻不许复刻旧案例、拒绝 PPT/流程图/可爱卡通/复杂架构。

## 白板管线追加的构图约束

除上游要求外，为了让画面能被自动拆分成绘制区域，出图时还要满足：

1. **主体之间留出明确空白走廊。** 每个要单独出场的主体（对应一条字幕事件）必须能被一个不与其它主体相交的矩形框住。相互穿插、重叠、共用轮廓的主体没法分区揭示。
2. **主体数量对齐字幕事件数。** 一幕里通常 2–4 个主体，与该幕的叙事事件一一对应（场景铺垫 → 关键人物/物体 → 动作或变化 → 反应/结果）。
3. **不要画满画面边缘。** 四角必须是干净纸底：渲染器靠四角取样判断背景色，边角有内容会让背景识别失准。
4. **线条不要过细过淡。** 笔迹揭示依赖阈值化后的墨迹像素，浅灰细线容易被判为背景而画不出来。
5. **小黑的实心黑身体是有意为之，但要给它留边界。** 实心块靠 `--ink-path grid`（默认）逐格铺满；
   **不要对含大面积实心黑的画面用 `--ink-path skeleton`**——骨架追踪只沿中轴线揭示，实心区域会留空。
   大面积实心黑在起笔阶段可能只画出轮廓、到添彩阶段才填实，这是正常的（先勾线后填墨）；
   若需要起笔阶段就填实，给渲染器加 `--solid-ink-gray 90`。

## 与渲染参数的关系

| 项 | 取值 | 说明 |
|---|---|---|
| 出图纸色 | `#F5EBD7` | 提示词里写死 |
| 渲染画布底色 | `#F6F1E3` | `stream_render.Config.canvas_hex`，渲染器会把接近背景的像素涂成它 |
| 笔迹路径 | `--ink-path grid`（默认） | 小黑的实心身体必须用 grid |
| 上色 | `--color-fill contour-wipe`（默认） | 线稿清晰、色块少，轮廓扫描效果最稳 |
| 实心墨块 | `--solid-ink-gray 90`（可选） | 让起笔阶段就把实心黑填满，而不是只勾轮廓 |
